## 22. Qualitative Anti-bloat Criteria

Until numeric thresholds are separately authorized:

- each file has one primary responsibility;
- common rules live in `_shared`;
- minimal entry lives in `START.md`;
- activation logic lives in `MANIFEST.md`;
- identity and output minimum live in `always`;
- frequent behavior lives in `hot`;
- common trigger-based behavior lives in `warm`;
- rare, high-risk, ambiguous, or escalation behavior lives in `cold`;
- provenance lives in `trace`;
- no family substitutes another family;
- no file copies kernels, profiles, or docs;
- no shard exists without trigger, function, or trace;
- no conditional content loads by default without operational need.

No numeric limit is introduced by this phase.

## 23. Anti-duplication Criteria

Authoritative homes:

- `_shared`: common and global rules;
- `START.md`: minimal entry and initial orientation;
- `MANIFEST.md`: activation, operational inventory, and dependencies;
- `always`: authority and minimum output;
- `hot`: frequent specific routine;
- `warm`: common trigger-based routine;
- `cold`: exception, risk, ambiguity, and escalation;
- `trace`: provenance and audit.

Duplication is blocked between:

- `_shared` and per-agent files;
- `START.md` and `MANIFEST.md`;
- `MANIFEST.md` and `SHARD_INDEX.md`;
- `always` and `hot/warm/cold`;
- `hot` and `warm`;
- `warm` and `cold`;
- Copilot and Codex entrypoints;
- kernel/profile sources and shards;
- `/docs` and support layer content.

## 24. Lazy-load Guardrails

- `START.md` as minimum entry;
