## 14. Current placeholder limitations for support layer

Current placeholders are insufficient for future support-layer templates
because they primarily model platform entrypoint metadata and target-level
Codex routing.

Limitations:

- they do not distinguish `_shared` support files from per-agent files;
- they do not model shard family, temperature, trigger, or dependency;
- they do not model trace provenance with enough structure;
- they do not separate source anchors from transformed support text;
- they do not express missing-source or stale-source behavior;
- they do not encode lazy-load activation rules;
- they do not distinguish platform values from target facts;
- they do not protect against monolithic `{{AGENT_BODY}}` reuse;
- they do not provide sufficient categories for `START.md`, `MANIFEST.md`,
  `always`, `hot`, `warm`, `cold`, or `trace`.

Therefore, current placeholders may inform inventory and risk, but future
support-layer planning needs a conceptual category taxonomy first.

## 15. Hybrid strategy

The safe future strategy is hybrid:

- preserve current platform-entrypoint placeholders for historical/dev-only
  evidence and for existing current template boundaries;
- do not retrofit current placeholders into support-layer semantics;
- introduce conceptual, namespaced placeholder categories for future
  support-layer planning;
- keep final syntax deferred until a separate syntax decision;
- require gates before any template creation;
- treat Target-dependent values as blocked until a Target is explicitly
  authorized;
- require traceability and non-copy guardrails before any future support-layer
  template work.

This strategy avoids both extremes: it does not discard current evidence, and
it does not reuse the current placeholder set as an unsafe universal model.

## 17. Required category classification vocabulary

Future category decisions must use this classification vocabulary:

- `REQUIRED_NOW_CONCEPTUAL`: the concept must exist in the taxonomy before
  later planning can remain traceable, but no executable syntax is selected;
- `OPTIONAL_CONCEPTUAL`: the concept may be useful later, but absence does not
  block this documentation phase;
- `TARGET_DEPENDENT`: the concept depends on a real Target and cannot be filled
  or inferred without explicit Target authorization;
- `SYNTAX_DEFERRED`: the concept can be named, but its final placeholder
  spelling, delimiter, escaping, or representation is deferred;
- `TEMPLATE_CREATION_BLOCKER_IF_UNDECIDED`: future template creation must
  block if the category is still undecided and needed by that template family;
- `NOT_SAFE_TO_DEFINE_NOW`: the concept would require facts, syntax, renderer
  behavior, parser behavior, schema behavior, Target data, or authorization not
  available in this phase.

## 20. Missing-placeholder behavior

Conceptual behavior for future phases:

- `REQUIRED` missing: block and fail closed.
- `OPTIONAL` missing: emit a safe empty value only when explicitly declared by
  the placeholder family; otherwise warn or block.
- `TARGET_DEPENDENT` missing: defer to a phase with explicit Target
  authorization and block rendering when the value is needed.
- `TRACE` missing: block template creation when traceability is a requirement.
- Unknown placeholder found: block.
- Unused placeholder after render: block.
- Multiline value invalid for the target format: block.
- Placeholder requiring a forbidden read: fail closed or ask for explicit
  scope; never broad-read.

This behavior is conceptual. It is not a runtime contract and does not define
block codes or stdout behavior.

## 21. Escaping and multiline conceptual policy

Conceptual policy:

- Markdown body placeholders must not insert operational authority that was not
  explicitly authorized by the source family and active phase.
- TOML output must be TOML-aware and must not use raw interpolation for strings,
  arrays, or bodies.
- YAML/frontmatter output must preserve valid strings, lists, and blocks.
- Paths must be normalized and must not escape the authorized output root.
- Lists must be represented as structures, not ad hoc strings.
- Nested placeholders must be prohibited or must block before rendering.
- Multiline values must be allowed only where the target format and family
  policy explicitly support them.
- Format-aware escaping must happen before any write in a future authorized
  phase.

This document does not implement escaping, create a parser, create a renderer,
or create fixtures.
