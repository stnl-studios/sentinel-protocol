## 12. Final syntax decision summary

Final conceptual decision:

- strategy: controlled hybrid strategy;
- conceptual delimiter: `{{...}}`;
- future support-layer names: semantically namespaced;
- current flat placeholders: legacy only for the existing
  platform-entrypoint and target-level templates;
- future case style: lowercase dot-separated names;
- segment readability: underscore is allowed inside name segments;
- nested placeholders: forbidden;
- unknown placeholders: block and fail closed;
- unused placeholders: block and fail closed;
- multiline identifiers: forbidden;
- multiline values: forbidden by default and only allowed by future
  family/format-specific decision;
- Target-dependent placeholders: classified, never filled without Target
  authorization;
- `{{AGENT_BODY}}`: prohibited as a monolithic support-layer body;
- renderability: this decision is documentary and not renderable.

## 14. Namespace decision

Classification: `NAMESPACE_REQUIRED`.

Future support-layer placeholder families must be semantically namespaced.
Required future families are:

- `shared`
- `agent`
- `shard`
- `trace`
- `platform`
- `target`

Namespace is mandatory for future support-layer placeholders because it reduces
collision risk, preserves traceability, separates platform-entrypoint concerns
from support-layer concerns, and prevents current flat placeholders from
becoming an unsafe universal model.

This namespace decision is conceptual taxonomy only. It is not an executable
schema.

## 15. Case style decision

Future names use lowercase dot-separated syntax as a conceptual convention.
Underscore is allowed inside individual segments for readability.

Uppercase snake-case names remain restricted to current legacy placeholders in
the existing platform-entrypoint and target-level template context.

This document does not create a regular expression, schema, validator, parser,
or renderer.

## 16. Allowed and disallowed characters

Allowed at the conceptual naming level:

- lowercase letters;
- digits;
- underscore inside name segments;
- dot as the namespace separator.

Disallowed at the conceptual naming level:

- whitespace;
- slash;
- backslash;
- path traversal;
- nested delimiters;
- characters that confuse TOML, YAML, or Markdown boundaries;
- characters implying a filesystem path or command.

This section is not an executable regular expression and must not be treated as
one.

## 17. Nested placeholder decision

Nested placeholders are forbidden.

Implications:

- a placeholder inside a placeholder value must block;
- recursive resolution is not allowed;
- no nested resolution order exists;
- no renderer for nested placeholders is authorized;
- nested delimiter content is invalid for future template creation.

## 18. Multiline placeholder decision

Multiline identifiers are forbidden.

Multiline values are forbidden by default. A future phase may allow multiline
values only by explicit family-specific and format-specific decision.

`{{AGENT_BODY}}` must not be used to reintroduce a multiline monolithic
support-layer body.

Markdown, TOML, YAML, and frontmatter behavior require future format-aware
decisions before any authorized rendering or writing can exist.

## 19. Unknown and unused placeholder behavior

Unknown placeholders block and fail closed.

Unused placeholders after any future authorized render also block and fail
closed.

Carrying unresolved placeholders forward as literal text is not allowed for
future template creation.

If a placeholder requires a forbidden read, the future process must block or
ask for explicit narrow scope. It must never broaden reading by default.

## 20. Target-dependent placeholder treatment

Target-dependent values are never filled in this phase.

Future Target-dependent placeholders must be classified as `target.*` concepts
or marked with the `TARGET_DEPENDENT` category before any later phase can decide
whether Target access is authorized.

Blocked until a later explicitly authorized Target phase:

- docs map;
- project surfaces;
- stack;
- commands;
- ownership;
- real paths;
- tooling;
- other Target facts.

Any future Target reading must be narrow-read. Target facts must never be
inferred.

## 21. Missing-placeholder behavior

Conceptual missing-placeholder behavior:

- `REQUIRED` missing: block and fail closed;
- `OPTIONAL` missing: safe omission only if the placeholder family declares
  it;
- `TARGET_DEPENDENT` missing: block when needed or defer to an explicitly
  authorized Target phase;
- `TRACE` missing: block when traceability is required;
- invalid value: fail closed;
- invalid multiline value: fail closed;
- placeholder requiring a forbidden read: fail closed or ask for explicit
  scope.

This is not a runtime contract and does not define stdout behavior or block
codes.

## 22. Escaping and anti-injection policy

Escaping is format-aware and deferred to a later authorized phase.

Conceptual anti-injection policy:

- Markdown must not receive operational authority that was not explicitly
  authorized;
- TOML must not use raw interpolation for strings, arrays, or bodies;
- YAML and frontmatter must preserve valid strings, lists, and blocks;
- paths must be normalized and target-root-relative;
- lists must be structural, not ad hoc strings;
- values must not contain real authorization;
- values must not contain invented Target facts;
- values must not contain `/docs` dumps;
- values must not contain literal copies of kernels;
- values must not contain literal copies of Senior Agent Profiles;
- values must not create load-all behavior;
- values must not alter authority boundaries;
- values must not create a third agent matrix;
- values must not contain path escape.

This policy does not implement escaping and does not authorize a renderer,
parser, schema, fixture, checker, or writer.

## 24. `{{AGENT_BODY}}` prohibition for support layer

`{{AGENT_BODY}}` must not be reused as the monolithic body for the future
support layer.

Reasons:

- it can collapse `START.md`, `MANIFEST.md`, and shard activation into one
  broad body;
- it can bypass lazy-load behavior;
- it can hide copied kernels, copied profiles, or `/docs` dumps;
- it can obscure traceability;
- it can reintroduce large entrypoint-style behavior into `.sentinel/agents/**`;
- it can undermine the matrix and support-layer separation.

Any future template creation proposal that relies on `{{AGENT_BODY}}` as the
support-layer body must block.
