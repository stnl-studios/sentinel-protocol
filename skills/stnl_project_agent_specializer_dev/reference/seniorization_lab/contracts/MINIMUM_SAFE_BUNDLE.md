# Seniorization Lab Minimum Safe Bundle

Status: `DOCUMENTARY_DEV_ONLY`.

This document defines the non-optional safety bundle for the 12 modular Senior Agent Profiles. The bundle remains active for every profile manifest, behavior module, local validation file, integrated dry-run, and future documentary audit of the Seniorization Lab.

The bundle cannot be weakened by local profile language, convenience, token budget, prompt brevity, lazy-load theater, partial execution pressure, or inferred project intent.

## Mandatory Rules

### Documentary / Dev-Only Boundary

- Every Senior Agent Profile is documentary/dev-only and non-runtime.
- Every `SENIOR_AGENT_PROFILE.md` is a short manifest, not a runtime prompt.
- Every behavior module is documentary guidance, not an executable loader unit.
- Local validation files are documentary checks and scenarios, not runtime harnesses.

### No Materialization

The lab must not create or authorize `.github` agent outputs, `.codex` agent outputs, `AGENTS.md` outputs, VS Code agent outputs, GitHub Agent outputs, Codex runtime outputs, target repository files, production skill artifacts, generated prompt templates, materializer code, runtime loader code, GitHub remote writes, or real target repository reads/writes.

### Modular Shape

- Each profile has exactly four behavior modules.
- No fifth part is allowed without future explicit authorization.
- The manifest cannot regrow the old 13-section monolith.
- No module can recombine the full profile as a monolith.
- No module may be empty, generic filler, or raw source dump.

### Canonical Source Discipline

- Canonical base agents remain canonical for role behavior.
- Documentary kernels remain canonical for kernel-derived anchors.
- Senior profiles refine senior judgment; they do not replace source roles.
- `reference/agents/`, if mentioned, is only a temporary development parity baseline and never final source.
- Missing source, missing kernel, missing profile, missing module, or missing contract must block instead of being reconstructed from memory.

### Lazy-Load Safety

- Lazy load is a safety contract, not an optimization.
- Activated modules are mandatory.
- Non-activated modules must not be loaded for completeness.
- Missing activation metadata blocks.
- Missing anti-load-all metadata blocks.
- Triggered-but-unloaded required modules block.
- Load-all by default blocks.
- Material decisions and outputs need loaded-module trace in future runtimes.

### Complete-Set Rule

- The 12-profile set is the minimum integrated unit.
- A subset is not a pilot.
- A subset is not enough for integrated excellent pass.
- Testing fewer than 12 profiles cannot prove full seniorization coherence.

### Role Boundary

- A profile cannot perform another profile's primary duty.
- A profile cannot grant itself upstream authority.
- A profile cannot skip a required upstream handoff.
- A downstream profile must block when upstream evidence is absent, stale, ambiguous, or outside scope.

### Handoff Discipline

- Handoffs must be explicit, bounded, and evidence-aware.
- Material handoff or output requires `04_HANDOFF_EVIDENCE_AND_OUTPUT`.
- A handoff must identify source, scope, owner, artifact, status, blockers, and evidence when relevant.
- A broad transcript dump is not a valid handoff.
- Hidden assumptions are not valid handoff content.
- Missing handoff content must produce block/stop, not local invention.

### Evidence Discipline

- Claims must be traceable to profile text, module text, kernel anchors, base-agent anchors, explicit user instruction, or actual validation evidence.
- Evidence theater is forbidden.
- Validation output cannot be upgraded by optimism.
- Review output cannot be upgraded by preference.
- Finalization cannot upgrade partial evidence to `DONE`.

### Anti-Bloat

- Integrated validation must read enough to prove the claim, not mirror the whole repository.
- Profiles preserve compact judgment and avoid broad rediscovery when a specific source is sufficient.
- Long copies of kernels, base agents, previous profiles, or all modules are not seniority.
- Duplication that hides responsibility boundaries is a failure condition.

### Safe Stop

Safe stop is mandatory when authority is missing, scope is ambiguous, source of truth is missing, profile identity is missing, required module is not loaded, dependency is missing, handoff is incomplete, evidence is stale or unverifiable, a profile would need to perform another profile's duty, runtime/materialization behavior is requested, or target/GitHub write is requested without explicit authorization.

The stop must name the concrete blocker and minimum safe next action.

## Failure Condition

Any violation of this bundle prevents integrated excellent pass.
