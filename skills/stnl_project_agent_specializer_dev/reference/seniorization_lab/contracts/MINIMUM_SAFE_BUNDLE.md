# Seniorization Lab Minimum Safe Bundle

Status: `DOCUMENTARY_DEV_ONLY`.

This document defines the non-optional safety bundle for the 12 Senior Agent
Profiles. The bundle remains active for every profile, every local validation
file, every integrated dry-run, and every future documentary audit of the
Seniorization Lab.

The bundle cannot be weakened by local profile language, convenience, token
budget, prompt brevity, partial execution pressure, or inferred project intent.

## Mandatory Rules

### Documentary / Dev-Only Boundary

- Every Senior Agent Profile is documentary/dev-only and non-runtime.
- No profile is a materialized agent prompt.
- No profile is a production template.
- No profile is a runtime loader, materializer, or executable agent pack.
- Local validation files are documentary checks and scenarios, not runtime
  harnesses.

### No Materialization

The lab must not create or authorize:

- `.github` agent outputs;
- `.codex` agent outputs;
- `AGENTS.md` outputs;
- VS Code agent outputs;
- GitHub Agent outputs;
- Codex runtime outputs;
- target repository files;
- production skill artifacts;
- generated prompt templates;
- materializer code;
- runtime loader code.

### Canonical Source Discipline

- Canonical base agents remain canonical for role behavior.
- Documentary kernels remain canonical for kernel-derived anchors.
- Senior profiles refine senior judgment; they do not replace source roles.
- Missing source, missing kernel, missing profile, or missing contract must
  block instead of being reconstructed from memory.

### No Invented Templates, Paths, Or Contracts

- Do not invent absent templates.
- Do not invent absent paths.
- Do not invent absent target files.
- Do not invent absent contracts.
- Do not infer target artifacts from similar projects.
- Absence means absence until the user or an authorized source supplies it.

### Complete-Set Rule

- The 12-profile set is the minimum integrated unit.
- A subset is not a pilot.
- A subset is not enough for integrated excellent pass.
- Testing fewer than 12 profiles cannot prove full seniorization coherence.

### Role Boundary

- A profile cannot perform another profile's primary duty.
- A profile cannot grant itself upstream authority.
- A profile cannot skip a required upstream handoff.
- A downstream profile must block when upstream evidence is absent, stale,
  ambiguous, or outside scope.

### Handoff Discipline

- Handoffs must be explicit, bounded, and evidence-aware.
- A handoff must identify source, scope, owner, artifact, status, blockers, and
  evidence when those are relevant to the next profile.
- A broad transcript dump is not a valid handoff.
- Hidden assumptions are not valid handoff content.
- Missing handoff content must produce block/stop, not local invention.

### Evidence Discipline

- Claims must be traceable to profile text, kernel anchors, base-agent anchors,
  explicit user instruction, or actual validation evidence.
- Evidence theater is forbidden: generic confidence cannot replace specific
  proof obligations.
- Validation output cannot be upgraded by optimism.
- Review output cannot be upgraded by preference.
- Finalization cannot upgrade partial evidence to `DONE`.

### Anti-Bloat

- Integrated validation must read enough to prove the claim, not mirror the
  whole repository.
- Profiles should preserve compact judgment and avoid broad rediscovery when a
  specific source is sufficient.
- Long copies of kernels, base agents, or previous profiles are not seniority.
- Duplication that hides responsibility boundaries is a failure condition.

### Safe Stop

Safe stop is mandatory when:

- authority is missing;
- scope is ambiguous;
- source of truth is missing;
- profile identity is missing;
- handoff is incomplete;
- evidence is stale or unverifiable;
- a profile would need to perform another profile's duty;
- a requested action would materialize agents or runtime artifacts;
- a requested action would write to GitHub or target paths without explicit
  authorization.

The stop must name the concrete blocker and the minimum safe next action.

## Failure Condition

Any violation of this bundle prevents integrated excellent pass.
