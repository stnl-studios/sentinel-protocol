## Structural Excellence

- The module contains exactly the requested profile files under
  `coder_backend_profile`.
- Required profile sections are present and substantive.
- Validation files are local to the module.
- No global contracts are created by this module.
- The one-of-12 statement is present and explicitly not a partial pilot.
- No profile for another agent is created or altered by this module.

## Kernel Preservation Excellence

- Critical coder-backend kernel anchors are preserved: strict executor role,
  `targeted-local` reading, execution only from valid package, backend-owned
  implementation, `READY`/`BLOCKED` terminal discipline, blocker behavior,
  contract safety, data rigor, auth/authz caution, backend/data guardrails, and
  executor evidence.
- Kernel content is distilled into operational judgment, not copied.
- The kernel remains the audit and semantic-preservation source.

## Role Boundary Excellence

- The canonical `coder-backend` role is preserved as backend executor, not
  planner, router, proof designer, package designer, designer, frontend/iOS
  coder, validation-runner, reviewer, finalizer, resync, materializer, or
  runtime loader.
- The profile does not expand authority beyond backend execution inside the
  approved package.
- Product, architecture, schema, auth, permission, payload, migration,
  persistence, integration, validation, review, and closure decisions remain
  outside coder-backend authority unless already supplied by valid package or
  source of truth.

## Backend Execution Excellence

- Heuristics are specific to backend APIs, services, controllers, routes,
  domain logic, persistence, migrations, auth, authorization, jobs,
  integrations, runtime, database access, schemas, and backend tests.
- The profile requires the smallest correct backend cut.
- The profile blocks instead of implementing when execution would be
  speculative.
- Execution remains low-token, delta-oriented, and evidence-producing.

## Package Boundary Excellence

- `EXECUTION PACKAGE`, `WORK_PACKAGE_ID`, `EXECUTION BRIEF`, `VALIDATION PACK`,
  and execution approval are required before execution.
- `OWNED_PATHS`, `DO_NOT_TOUCH`, `DEPENDS_ON`, `BLOCK_IF`, change rules,
  acceptance intent, and run/check expectations are binding.
- Owned-path insufficiency, do-not-touch conflicts, dependency conflicts, and
  block-if conditions are blockers, not local decisions.
- Package insufficiency is reported rather than repaired by the executor.

## Contract/Semantics Excellence

- API, route, request, response, status code, error shape, event payload,
  shared schema, public behavior, generated type, and consumer compatibility
  are protected from unsupported drift.
- Existing contracts are preserved when authorization to change them is absent.
- Shared frontend/iOS contract mismatch blocks or is routed upstream rather
  than silently transferred downstream.
- Vendor-specific details do not leak into public API, schema, domain, or
  stable contracts without explicit authority.

## Auth/Authz Excellence

- The profile treats authentication, authorization, tenant/user scoping,
  resource ownership, roles, permissions, guards, audit behavior, and error
  visibility as security-sensitive backend contract surfaces.
- Ambiguity in auth/authz produces a blocker unless existing contract can be
  safely preserved.
- The profile does not permit default access behavior, copied guard behavior,
  or permission assumptions by local preference.

## Persistence/Migration Excellence

- Persistence, data access, query safety, ORM/NoSQL/cache behavior, migrations,
  indexes, transaction boundaries, bounded access, data lifecycle, backfills,
  rollback posture, reader/writer compatibility, and data consistency are
  explicitly protected.
- `stnl_backend_sql_quality` is recognized when persistence or data behavior is
  touched.
- Unsafe migration, destructive data operation, unbounded query, or transaction
  ambiguity blocks execution.

## Integration/Runtime Excellence

- Jobs, queues, scheduled work, events, webhooks, SDKs, external APIs,
  idempotency, retries, ordering, timeouts, rate limits, failure recovery,
  config, env, secret handling, logs, metrics, and runtime behavior are covered.
- External side effects, especially near transaction boundaries, are treated as
  production-impacting.
- Integration ambiguity blocks execution instead of becoming local preference.

## Handoff Excellence

- Minimum input and output are explicit.
- Handoffs separate facts, changes, local decisions, evidence, blockers, risks,
  limitations, and next owner.
- Handoff to `validation-runner` enables validation of a real backend artifact
  without creating final validation or review.
- Reviewer-sensitive risk is named without performing review.
- Ambiguous contract, package, auth, migration, or integration decisions are
  resolved upstream or blocked rather than exported downstream.

## Evidence Discipline Excellence

- The profile distinguishes applied implementation from intention, executed
  command from suggested command, local check from formal validation, executor
  evidence from runner verdict, reviewer decision, and finalizer closure.
- `READY` requires changed paths or equivalent implementation evidence.
- Skipped, unavailable, or failed checks are reported honestly.
- Partial edits without safe completion force explicit blocker handling.

## Anti-Overreach Excellence

- `coder-backend` does not route, plan, create validation pack, create
  execution package, resolve design/UX, implement frontend/iOS work, execute
  validation, review, finalize, resync, or rewrite out-of-scope profiles,
  kernels, productive skills, templates, materializers, `sentinel.mjs`, smoke
  scripts, or runtime targets.
- The profile prohibits downstream role takeover and does not turn seniority
  into additional authority.

## Anti-Bloat Excellence

- No long copy-paste from kernel, base agent, `orchestrator_profile`, or
  `planner_profile` exists.
- The profile is not a general project manual or complete backend engineering
  manual.
- The content stays focused on backend execution, package boundary, contracts,
  data, auth, runtime risk, blockers, evidence, reading budget, and handoff.
- Runtime-oriented instructions are absent.

## Scenario Excellence

- Golden scenarios cover clear backend execution, missing package, API contract
  ambiguity, auth/authz ambiguity, persistence/migration ambiguity,
  insufficient owned paths, do-not-touch conflict, validation-pack mismatch,
  shared frontend/iOS contract mismatch, integration/job ambiguity, evidence
  weakness, and runtime leakage.
- Each scenario includes scenario, input, expected guidance, excellent signal,
  and failure modes.
- Scenarios are sufficient for future audit without becoming a runtime test
  suite.
