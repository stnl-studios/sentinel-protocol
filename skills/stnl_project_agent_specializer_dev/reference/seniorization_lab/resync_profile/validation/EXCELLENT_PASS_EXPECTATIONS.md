# resync Senior Profile Excellent Pass Expectations

Future audit target:

`resync Senior Agent Profile: EXCELLENT PASS`

Senior profile audit target:

`SENIOR_AGENT_PROFILE_AUDIT: EXCELLENT PASS`

## Structural Excellence

- The module contains exactly the requested profile files under
  `resync_profile`.
- Required profile sections are present and substantive.
- Validation files are local to the module.
- No global contracts are created by this module.
- The third-created statement is present and explicitly not a partial pilot.

## Kernel Preservation Excellence

- Critical resync kernel anchors are preserved: finalizer/requested-resync
  entry, factual delta qualification, shared/local/normative classification,
  minimal target selection, targeted-local reading, no broad docs campaign, no
  runtime/temp source of truth, safe stop, and no downstream role takeover.
- Kernel content is distilled into operational judgment, not copied.
- The kernel remains the audit and semantic-preservation source.

## Role Boundary Excellence

- The canonical `resync` role is preserved as final-context synchronization
  specialist and drift-reduction boundary.
- The profile does not expand authority beyond authorized context alignment.
- Orchestration, planning, validation design, execution package design, design,
  implementation, validation execution, semantic review, finalization, closure
  status, `DONE`, and `resync: yes/no` remain outside resync authority.

## Resync Excellence

- Heuristics are specific to accepted final state, final facts, final
  decisions, residual risks, blockers, sync source, sync target, and
  future-context notes.
- The profile blocks instead of inventing source, target, authorization, or
  final state.
- Resync stays low-token, bounded, auditable, and continuity-oriented.

## Finalizer Handoff Excellence

- The profile requires finalizer handoff or explicit equivalent authorization
  when applicable.
- Finalizer ownership of `resync: yes/no` is preserved.
- A valid orchestrator replay can preserve finalizer-owned context, but runtime
  temp recovery and loose context are rejected.

## Final State Preservation Excellence

- Accepted final facts and decisions are carried forward faithfully.
- Residual risks stay residual risks.
- Residual blockers stay blockers.
- Closed decisions are not reopened, softened, or normatively rewritten without
  explicit authorization.

## Context Sync Boundary Excellence

- The profile differentiates resync from new round, correction, review,
  validation, finalization, planning, execution-package design, design, and
  implementation.
- The output stays focused on sync source, sync target, facts, decisions,
  evidence, residual risks, blockers, and future-context notes.
- General documentation cleanup, changelog, postmortem, release note, repo
  digest, and whole-round narrative are rejected as resync substitutes.

## Handoff Excellence

- Minimum input and output are explicit.
- Handoffs separate facts, decisions, evidence, residual risks, blockers,
  future-context notes, and intentionally unsynchronized material.
- Handoffs are compact and auditable.
- Ambiguous authority, owner, gate, target, or source returns to orchestrator,
  DEV, or finalizer instead of being guessed.

## Evidence Discipline Excellence

- The profile distinguishes finalizer handoff, final decision, accepted
  terminal status, final artifact, canonical source of truth, loose context,
  and informal claim.
- "Seems finalized", absence of visible error, context volume, stale notes,
  runtime logs, scratchpads, and generated reports do not replace final source.
- The profile detects when the correct result is block/ask rather than sync.

## Anti-Overreach Excellence

- The resync does not route as orchestrator except to signal return when owner
  or gate is unclear.
- The resync does not plan, create `EXECUTION BRIEF`, create validation
  strategy, create `VALIDATION PACK`, create `EXECUTION PACKAGE`, resolve
  design, implement, execute validation, review, finalize, alter terminal
  status, or rewrite out-of-scope profiles and kernels.
- The profile prohibits downstream role takeover and does not turn seniority
  into additional authority.

## Anti-Bloat Excellence

- No long copy-paste from kernel, base agent, `orchestrator_profile`, or
  `planner_profile` exists.
- The profile is not a general project manual.
- The content stays focused on final state, facts, decisions, evidence,
  residual risks, blockers, reading budget, sync target, and future context.
- Runtime-oriented instructions are absent.

## Scenario Excellence

- Golden scenarios cover clear finalizer-requested resync, missing handoff, new
  round disguise, review/validation takeover, closed-decision rewrite,
  ambiguous source of truth, documentation dump, and runtime leakage.
- Each scenario includes scenario, input, expected guidance, excellent signal,
  and failure modes.
- Scenarios are sufficient for future audit without becoming a runtime test
  suite.

## Third-Created Consistency Excellence

- This profile reuses the approved documentary shape while remaining
  resync-specific.
- It is not treated as a pilot, subset rollout, or partial validation strategy.
- It does not create artificial demand for a subset of agents.
- It does not return Rodada A to active task status.
- It remains compatible with future repetition for the other profiles.

## Quality Bar

The profile is excellent only if it has resync-specific content, avoids generic
seniority language, contains no runtime leakage, contains no long copy-paste,
contains no long copy of `orchestrator_profile` or `planner_profile`, performs
no downstream role takeover, does not revive Rodada A as an active task, does
not treat this module as a partial pilot, defines boundaries between resync,
orchestration, planning, validation design, execution package, design,
implementation, validation, review, finalization, and new round, preserves
final state, depends clearly on finalizer handoff or authorization when
applicable, defines clear blockers, provides actionable heuristics, defines a
reading budget compatible with resync, gives enough scenario coverage for
future audit, and remains compatible with future repetition for the other
profiles.
