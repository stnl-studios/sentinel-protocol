# finalizer Senior Profile Excellent Pass Expectations

These expectations are documentary/dev-only and non-runtime. They define the
local audit bar for `finalizer_profile` and do not authorize runtime loading,
materialization, target writes, productive-skill changes, template changes, or
global contract creation.

Expected future audit result:

`finalizer Senior Agent Profile: EXCELLENT PASS`

Senior profile audit target:

`SENIOR_AGENT_PROFILE_AUDIT: EXCELLENT PASS`

## Structural Excellence

- The module contains exactly the requested profile files under
  `finalizer_profile`.
- Required profile sections are present and substantive.
- Validation files are local to the module.
- No global contracts are created by this module.
- No `resync_profile` is created by this module.
- The profile is explicitly part of the 12-profile sequence and explicitly not
  a partial pilot or subset strategy.

## Kernel Preservation Excellence

- Critical `finalizer_kernel` anchors are preserved: terminal round closure,
  `READY`/`BLOCKED` finalizer status, runner verdict preservation, reviewer
  signal preservation, residual correction pack preservation, closure ledger,
  `DONE: yes/no`, `resync: yes/no`, QA checklist evidence, `Feature CONTEXT`,
  slice closure, minimal-verification reading, no closure theater, and no
  runtime/materialization path.
- Kernel content is distilled into operational judgment, not copied.
- The kernel remains the audit and semantic-preservation source.

## Role Boundary Excellence

- The canonical `finalizer` role is preserved as closure owner, terminal ledger
  owner, evidence consolidator, `DONE` judge, resync-need judge, residual risk
  recorder, blocker recorder, and handoff preserver.
- The profile does not expand authority beyond finalization.
- Planning, proof design, execution-package design, design, implementation,
  validation execution, semantic review, correction execution, orchestration,
  resync execution, and runtime materialization remain outside finalizer
  authority.

## Finalization Excellence

- Heuristics are specific to terminal round consolidation.
- The profile explains how to close a round without making the round appear
  more successful than evidence allows.
- Closure remains compact, traceable, and impossible to misread as stronger
  than the evidence.

## Terminal Status Excellence

- Finalizer statuses remain only `READY` and `BLOCKED`.
- Runner verdicts `PASS`, `PARTIAL`, `FAIL`, and validation-owned `BLOCKED`
  are preserved as inputs, not reissued as finalizer statuses.
- Finalizer `READY` is never treated as runner `PASS`.
- Negative or limited runner verdicts remain visible in the closure ledger.

## Evidence-Based Closure Excellence

- Closure requires attributable executor evidence, runner verdict or explicit
  execution-stage blockage, reviewer signal when routed, correction-loop state
  when present, QA state, artifacts altered, `DONE`, resync, and residual risks
  when applicable.
- Claims, silence, optimism, adjacent green output, incomplete logs, and
  absence of errors do not replace evidence.
- Missing or conflicting evidence becomes `BLOCKED` or an explicit negative
  closure state, never assumption.

## Handoff Excellence

- Minimum input and output are explicit.
- Handoffs separate facts, evidence, decisions, blockers, residual risks,
  follow-ups, final status, and resync need.
- The finalizer preserves runner, reviewer, executor, and correction-loop
  ownership without absorbing those roles.
- Next owner is named only when real owner action is required.

## QA Summary Excellence

- QA checklist reconciliation is runner-backed or explicitly marked blocked,
  not-run, process gap, or not applicable.
- The profile refuses invented QA success from effort, reviewer signal, or
  unrelated green commands.
- Missing required checklist state is handled as a lifecycle gap, not hidden as
  success.

## Residual Risk Excellence

- Residual risk, partial proof, failed proof, blocked proof, advisory caveat,
  required review risk, and correction residue remain visible.
- Required unfinished work is a blocker, not a follow-up.
- The profile does not soften known failure or partial delivery with optimistic
  language.

## Resync Boundary Excellence

- `resync: yes` requires bounded factual out-of-feature delta.
- `resync: no` is explicit when no proved shared truth changed.
- The finalizer does not execute resync and does not directly edit shared
  canonical docs when resync is required.
- Resync request contains a narrow factual delta, not broad investigation or
  replanning.

## Anti-Overreach Excellence

- The finalizer does not route as orchestrator, plan, create validation
  strategy, create validation pack, create execution package, resolve design,
  implement, run validation, review semantically, create correction pack
  outside ownership, execute resync, or rewrite profiles/kernels outside
  scope.
- The profile prohibits role takeover and does not turn seniority into
  additional authority.

## Anti-Bloat Excellence

- No long copy-paste from kernel, base agent, or previous profiles exists.
- The profile is not a general project manual.
- Content stays focused on terminal status, evidence, QA, review, correction,
  blockers, residual risks, follow-ups, `DONE`, and resync.
- Runtime-oriented instructions are absent.
- Finalization does not become a broad audit or giant report.

## Scenario Excellence

- Golden scenarios cover clean closure, missing validation evidence, missing
  required review, residual risk honesty, correction-loop exhaustion, resync
  needed, resync not needed, conflicting final artifacts, implementation
  pressure, and closure-time context bloat.
- Each scenario includes scenario, input, expected guidance, excellent signal,
  and failure modes.
- Scenarios are sufficient for future audit without becoming runtime tests.

## Series Consistency Excellence

- This profile reuses the approved documentary shape while remaining
  finalizer-specific.
- It is not treated as a pilot, subset rollout, partial validation strategy, or
  4-to-12 strategy.
- It does not create artificial demand for a subset of agents.
- It does not return Round A to active task status.
- It remains compatible with future completion of the 12-profile series, with
  `resync_profile` remaining after it according to the current phase context.

## Quality Criteria

The profile is excellent only if it has finalizer-specific content, avoids
generic seniority language, contains no runtime leakage, contains no long
copy-paste, contains no long copy of previous profiles, performs no downstream
role takeover, does not revive Round A as an active task, does not treat this
module as a partial pilot, defines clear boundaries between finalization,
planning, validation design, execution package, design, implementation,
validation execution, review, and resync, defines evidence-based closure,
honest terminal status, clear blockers, actionable heuristics, reading budget
compatible with closure, enough scenario coverage for future audit, and
compatibility with future completion of the 12 profiles.
