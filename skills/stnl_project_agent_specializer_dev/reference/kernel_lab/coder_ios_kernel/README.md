# coder_ios_kernel

Status: `CODER_IOS_KERNEL: CLEAN_EXCELLENT_PASS`.

This is a dev-only documentary, contractual, and semantic kernel-lab bundle for
the canonical `coder-ios` base agent. It validates the local dev snapshot
`skills/stnl_project_agent_specializer_dev/reference/agents/coder-ios.agent.md`
against `templates/agents/coder-ios.agent.md` and against the narrowed
`coder_ios_kernel` contract.

The bundle is not a runtime pass, production pass, target-repo pass,
materialization pass, runtime loader, materializer, fixture set, generated
report, target artifact, productive-skill authorization, GitHub write
authorization, target repository write authorization, canonical-template
mutation, or active runtime adoption path.

## Scope Limits

`coder_ios_kernel` preserves only the base agent behavior needed for a native
iOS specialist executor:

- role class `executor`;
- `targeted-local` reading;
- entry during execution only for a clear native iOS Swift app surface;
- Swift and SwiftUI as the default implementation path;
- UIKit interop only when already present in the touched path or materially
  required by the cut;
- required inputs: `EXECUTION PACKAGE` with `WORK_PACKAGE_ID`, `EXECUTION
  BRIEF`, `VALIDATION PACK`, required quality guardrails when present, and
  minimum affected iOS context;
- output: native iOS implementation plus concise execution delta, changed paths
  or equivalent implementation evidence, checks run or honestly not run,
  residual risk, and exact blocker only when `BLOCKED`;
- terminal statuses only `READY` and `BLOCKED`.

It does not plan, design proof, compile or reinterpret an execution package,
run validation as the validation owner, perform review, close the round,
perform resync, decide `DONE`, decide `resync: yes/no`, write durable
documentation, use runtime/temp paths as source of truth, authorize GitHub
writes, authorize target repository writes, authorize materialization, or
authorize productive-skill behavior.
