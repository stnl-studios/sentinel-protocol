# Finalizer Kernel Behavior Parity Spine

Status: `FINALIZER_KERNEL: CLEAN_EXCELLENT_PASS`.

This spine is documentary/dev-only. It does not authorize runtime, production,
materialization, materializer, runtime loader, GitHub write, target repo write,
generated reports, fixtures, target artifacts, productive skill activation,
template mutation, snapshot mutation, or automatic future promotion.

## Non-Reducible Semantics

The kernel preserves these irreducible behaviors from the base `finalizer`
agent:

- closure after `validation-runner.agent.md`, after `reviewer.agent.md` when
  routed, or after explicit execution-stage blockage before validation;
- preservation of runner verdict `PASS`, `PARTIAL`, `FAIL`, or validation-owned
  `BLOCKED` as input, not finalizer status;
- preservation of execution-stage blockage without inventing a runner verdict;
- reviewer signal preservation with `required` or `advisory` force and material
  structural risk;
- residual correction pack preservation with issue IDs, fingerprints or root
  causes, attempts, and budget state;
- minimum honest `Feature CONTEXT` update;
- explicit `DONE: yes/no` judgment;
- explicit `resync: yes/no` judgment;
- closure ledger before `READY`;
- `qa_checklist.md` reconciliation only from runner-backed evidence, or
  explicit process gap;
- post-slice closure record with `SL-001` style ID and
  `concluida|parcial|bloqueada` classification;
- `minimal-verification` reading;
- no closure theater.

## Closure Truth

The finalizer closes on earned truth, not effort, optimism, or green output
alone. It separates intended cut, actual change, validation reality, review
reality, residual correction, documentation consequence, `DONE` judgment, and
resync judgment before emitting `READY`.

`READY` is allowed only when closure was honestly consolidated and the ledger is
complete. `READY` is not runner `PASS`; runner `PASS` is only preserved as
validation input.

`BLOCKED` is required when closure would require guessing, when runner verdict
and observed evidence materially contradict each other, when required review is
missing or exposes unresolved material structural risk, when execution-stage
blockage cannot be preserved honestly, when residual correction pack is missing
after budget exhaustion, when factual delta cannot be bounded for resync, when
the ledger is incomplete, or when slice evidence is insufficient.

## Required Boundary Behavior

The finalizer does not implement, correct, patch, replan, redefine the cut,
reinterpret the execution package, redesign proof, run validation, replace
`validation-runner.agent.md`, replace `reviewer.agent.md`, execute resync, or
write shared canonical docs directly.

The finalizer does not create `DONE` automatically from runner `PASS`, effort,
or green checks. It does not create `DONE.md` in an active SPEC with
`closure_status: not_closed`. It does not invent QA checklist success. It does
not create `qa_checklist.md` as a substitute for SPEC lifecycle ownership.

The finalizer does not use `PLAN.md` or legacy phase artifacts as durable
documentation, and does not search `workspaceStorage`, `chat-session-resources`,
`content.txt`, scratchpads, or runtime temporary files for handoffs.

## Durable Documentation Floor

The only durable documentation outcome preserved by this kernel is the minimum
truthful finalizer scope: `Feature CONTEXT` delta, optional milestone-grade
`DONE`, applicable `qa_checklist.md` reconciliation from runner-backed
evidence, post-slice closure declaration when slice-scoped, and factual resync
request delta when needed. Shared canonical docs are not finalizer write
targets when `resync.agent.md` is the correct owner.
