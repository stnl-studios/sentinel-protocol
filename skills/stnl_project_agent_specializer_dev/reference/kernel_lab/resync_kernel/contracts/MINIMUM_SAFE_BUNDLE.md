production, materialization, materializer, runtime loader, GitHub write, target

## Required Semantic Floor

Every valid resync kernel bundle must preserve:

- finalizer-only entry;
- finalizer decision ownership for `resync: yes/no`;
- resync execution or coordination of only the requested factual sync;
- role class `sync`;
- reading scope `targeted-local`;
- statuses `READY` and `BLOCKED` only;
- factual-delta qualification;
- shared versus feature-local versus normative classification;
- limited durable docs targets;
- `Feature CONTEXT` as read-only unless explicitly authorized;
- ADR and normative `RULES` as non-default edit ownership;
- runtime/temp handoff path ban;
- prohibition against implementation, validation, review, planning, coding,
  closure, `DONE`, QA success invention, runtime, production, and
  materialization claims.

## Required Harness Floor

The static harness must validate exact file allowlist, safe file types, no
symlinks, snapshot parity, frontmatter preservation, semantic anchors, role
boundaries, durable docs, finalizer relationship, runtime/temp bans, code-fence
scanning, import guard, and forbidden claims by semantic family with local
polarity.

The golden harness must run the static harness as preflight, enforce the
scenario structure, include positive and negative scenarios for real resync

polarity so prohibitive claims remain valid while positive authority drift is
blocked.
